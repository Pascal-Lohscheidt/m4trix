# Changelog

All notable changes to `@m4trix/core`. The full release notes, with every feature, are in the [docs changelog](https://m4trix.dev/docs/project/changelog).

## Unreleased (0.18.0)

0.18.0 makes runs explicit (they end exactly once, within limits), validates everything that crosses the network's boundaries, keeps history per user in a pluggable store as encoded JSON, adds context folds (typed, cached, compactable model context), and trims the public API to what is meant to be used. Most apps need the migration notes under **Breaking changes**; each one says what to change.

### Breaking changes

- **Runs end, and their streams close.** A run ends exactly once with `m4trix:run.completed`, `m4trix:run.failed` or `m4trix:run.cancelled`, and an exposed stream closes after that event instead of staying open until the client leaves. An agent that throws now fails its run (`onAgentError: 'fail'`, the default) and aborts the run's other agents.
  _Migrate:_ declare what finishes a run with `endsOn(event, when?)` in `AgentNetwork.setup()`, or call `complete()` from agent logic; otherwise a run fails after `idleTimeout` (60 seconds without events) or at `maxDuration` (10 minutes). Pass `onAgentError: 'continue'` to keep the old "log and go on" behavior (it publishes `m4trix:agent.error`). Event names starting with `m4trix:` are reserved.

- **Reserved names are refused from outside.** Only the runtime publishes `m4trix:` events (run lifecycle, fold checkpoints). `plane.publish`, `publishToChannels` and `publishAndAwait` fail with `ReservedEventNameError` (`eventName`) in their error channel, and publish nothing; a proxy's `publish` / `withMeta(...).publish` / `publishInbound` reject with it; `emitStartEvent` throws `ExposeValidationError` (a 400, issue at `name`). Code that relays client-chosen event names could otherwise end a run for its clients or forge a fold checkpoint that every later read restores.
  _Migrate:_ stop publishing `m4trix:` events yourself; effects around the plane's publish methods that were typed with `never` errors now carry `ReservedEventNameError | NonJsonPayloadError` (the second for payloads the store cannot keep, see **Payloads must be storable as JSON**; handle both, or widen the type).

- **Runs have default limits.** A run fails (`kind: 'limit-exceeded'`) when an event is more than 25 hops from the start event (`maxDepth`) or the run publishes more than 1000 durable events (`maxEvents`). Emits get `meta.causationId` = the trigger's `eventId` and `meta.ts` = publish time (they used to copy the trigger's).
  _Migrate:_ raise the limits, or pass `Infinity`, in the setup options, `network.run()` or `registerSSEStream()`.

- **History is read on demand: `ctx.history`.** `runEvents` and `contextEvents` are gone from agent logic and from `EventAggregator` callbacks, as are `EventPlane.getRunEvents` / `getContextEvents`.
  _Migrate:_ `await history.run()` for the run's durable events; `await history.context({ limit, before })` for a page `{ events, cursor }` of the conversation (oldest first; pass `cursor` as `before` for older events). Outside an agent: `plane.history({ runId, contextId, principalId })`.

- **`AgentNetworkStore` is async and keyed by tenant.** The interface is `append(key, event)`, `readRun(key, runId)`, `readContext(key, { limit, before, after, names })` (a page `{ events, cursor, head, reset }`), and optional `readLatest(key, names)` and `deleteContext(key)`, with `key = { namespace, contextId }`. `storeEvent`, `getEvents`, `getContextEvents`, `getFullStore`, `persist` and `load` are removed. Stored events carry `channels`; transient events are never stored. The in-memory store now expires conversations (30 minutes) and keeps at most 1000.
  _Migrate:_ rewrite custom stores against the new interface ([Writing a store adapter](https://m4trix.dev/docs/api-reference/agent-network#writing-a-store-adapter)), and check the result with `runStoreContract` from `@m4trix/core/testing`. Scope every read and write by `namespace` and `contextId`, and return events exactly as appended: JSON, unchanged, `channels` on every read. `readContext` must support, besides `limit` and `before` (backward pages with a `cursor`): `after` (forward reads from a `head`; rejected together with `before`), `names` (only events with one of them, cursors staying positions in the whole log), a `head` on every non-empty page, and `reset: true` with the current history from its start for an `after` cursor of a deleted, expired or unrecognised history. Positions only grow (an event appended while a cursor is out lands after it), and cursors are persisted in fold checkpoints, so keep their format stable. `readLatest` (an indexed lookup for `history.latest`) and `deleteContext` are optional. Pass the store as `AgentNetwork.setup(cb, { store })`; tune the default with `createInMemoryNetworkStore({ ttl, maxContexts })`.

- **History holds encoded, frozen JSON.** The runtime stores each durable event as a deep-frozen JSON copy, its payload encoded with its event's schema (`S.encode`), so nothing stored shares an object with what agents received. `history.run()`, `history.context()`, `history.latest()`, `plane.history()` and custom stores see that form: a `Date` under `S.Date` is an ISO string, `S.NumberFromString` a string, an `Option` `{ _tag, value }`, a field renamed with `S.fromKey` is under its encoded key (plain schemas look as before). The in-memory store hands out the frozen objects it got (writing to them throws); a database store returns fresh, unfrozen ones. An agent's emit is captured when it is called: changing the payload object afterwards changes nothing stored. A non-finite `meta.ts` or `meta.depth` is stamped like a missing one.
  _Migrate:_ decode what you read from history for events with transforming schemas (`Event.decode(event)` or `S.decodeUnknownSync(Event.payload)(event.payload)`). `history…filter(Event.is)` **silently matches nothing** for them: `Event.is` checks the decoded form, and the stored one fails it without an error. Or read the conversation through a context fold, which decodes. Custom stores must return events exactly as appended (JSON, `channels` on every read, no reviving of values) and must not add fields to the frozen event `append` gets (copy it first); `runStoreContract` checks the rest.

- **Payloads must be storable as JSON.** The stored copy is what `JSON.stringify` writes: a value with a `toJSON` method is stored as what it returns (a `Date` in an `S.Unknown` field as its ISO string, which folds, history and streams then see, while the agents that got the event live still see the `Date`), and undefined properties are left out; when a `toJSON` changed a value, the copy must decode with the event's schema again. Effect values in `S.Unknown` fields are stored as their `toJSON`, Effect's debug format (an `Option` as `{ _id, _tag, value }`), not a contract. What JSON cannot hold is refused: a `Map`, `Set`, `Error`, `Data.struct` or class instance without a `toJSON`, a `bigint`, `NaN`, `undefined` in an array, a getter or a `toJSON` that throws, and a `Date` under `S.DateFromSelf` (its ISO string is no `Date`).
  - An agent's emit of such a payload throws `EmitValidationError` (`reason: 'invalid-payload'`, with the message `… is not JSON-compatible: a Map at output[0].rows` and the value's `path` in the issue), as does one its schema cannot encode; the run fails like for any invalid emit.
  - An event published from outside is encoded with the schema the network knows for its name (a payload not of that type is stored as given). One JSON cannot hold is refused by the publish itself: `plane.publish`, `publishToChannels` and `publishAndAwait` fail with the new `NonJsonPayloadError` (`eventName`, `path`, `found`, e.g. `a Map`) in their error channel, a proxy's `publish` / `withMeta(...).publish` / `publishInbound` rejects with it before claiming the run, and `expose()` answers such a start event with a 400. Nothing is published or retried, and the run goes on.
  _Migrate:_ give non-JSON values a schema that encodes them (`S.Date` instead of `S.DateFromSelf`) or convert them before emitting (the wiring check warns, `event-not-storable`); where folds need a `Date` from an `S.Unknown` field typed, give it a schema. Handle `NonJsonPayloadError` where you publish from outside.

- **No secrets in durable events.** `S.Redacted` encodes to the secret itself, which would then be stored and streamed, so a durable event's schema may not hold one: `AgentNetwork.setup()` throws `NetworkWiringError` with the new error code `durable-event-redacted`, wherever the `Redacted` is (nested, optional, a union member, a class, behind `S.suspend`). Transient events may carry one: they are never stored, and streams send it as `"<redacted>"` (the whole payload, when the schema cannot encode it).
  _Migrate:_ mark events that carry `S.Redacted` transient, or take the secret out of the payload.

- **Streams send payloads encoded with their schema.** Live SSE streams, the `ExposedStream` a `createStream` consumer reads, and custom proxies' `subscribeOutbound` send each payload in its stored form, encoded with its event's schema, exactly what a resumed stream (`Last-Event-ID`) replays from the store. Before, the live stream sent the decoded payload through `JSON.stringify`, so the two differed for transforming schemas. Transient events are encoded the same way as they are sent. Plain schemas are unchanged. What changes on the wire: `S.NumberFromString` and `S.BigInt` arrive as strings (a `bigint` used to break `JSON.stringify`: the stream logged a warning and sent a lossy copy), an `Option` as `{ _tag, value }` without the `_id: "Option"` `JSON.stringify` wrote, and a field renamed with `S.fromKey` under its encoded key. `S.Redacted` values of transient events are still sent as `"<redacted>"`, never the secret (durable events cannot hold them, see above).
  _Migrate:_ clients of events with transforming fields decode them with the event's schema, e.g. `S.decodeUnknownSync(Event.payload)(data.payload)`.

- **Proxy publishes and request bodies are decoded as wire data.** A proxy's `publish` / `withMeta(...).publish` / `publishInbound` decode each payload with the schema the network knows for its event name, as `subscribeOutbound` encodes it, so agents get decoded values (they used to get the payload as sent); a request body without `onRequest` is decoded with its trigger's schema the same way. Payloads are decoded first, whatever they look like: for string codecs (`S.StringFromBase64`, `S.parseJson(S.String)`, `S.StringFromUriComponent`) `"aGk="` is base64 for `"hi"`, where a value that already passed as the type used to be taken as it was (and then stored encoded twice). A payload that does not decode but already is a value of the type is still taken as it is; one that is neither is published (and stored) as given by proxies, and refused with a 400 for request bodies, as before.
  An event made with `Event.make` / `makeBound` (or their Effect variants) is a value already: proxies publish it as it is, like `plane.publish`, so `api.publish(Upload.make({ file: 'dGVzdA==' }))` reaches agents as `file: 'test'`, not decoded twice.
  _Migrate:_ bridges that relay `subscribeOutbound` output back in now round-trip correctly; publish typed values through a proxy as `Event.make(…)` / `Event.makeBound(…)` results (a copy or an object literal is wire data, which only matters for string-to-string codecs such as `S.StringFromBase64`).

- **`auth` returns a principal.** `AuthResult` is `{ allowed: true; principal?: { id, ...claims } } | { allowed: false; status?; message? }`. History is stored and read per `(principal, contextId)`; events of another principal's run are refused, and reusing another principal's `runId` is a 403. Proxy `publish` / `withMeta` / `publishInbound` ignore `meta.principalId`.
  _Migrate:_ return `{ allowed: true, principal: { id: user.id } }` from `auth` (without a principal every request shares one anonymous namespace, as before), and pass `{ principal }` explicitly to proxy publishes.

- **Tools reject with typed errors.** `Tool.of()` throws `ToolDefinitionError` for names outside `^[a-zA-Z0-9_-]{1,64}$`, and `define()` for input schemas that are not objects or cannot become JSON Schema. `execute` rejects with `ToolInputError`, `ToolExecutionError` (the tool's error is its `cause`), `ToolOutputError` or `ToolTimeoutError` instead of raw `ParseError`s, fiber failures or the tool's own error.
  _Migrate:_ catch the new error classes (or use `executeForModel()` / `toToolModelError()` to hand the error back to the model); read your own error from `error.cause`.

- **Emits, params and requests are validated.** An agent or tool may only emit events declared in its `.emits([...])`, with a valid payload, to a channel that accepts it; anything else throws `EmitValidationError` and fails the invocation (run failure `kind: 'invalid-emit'`). Agents without `.emits()` may emit nothing. Channels with `.events([...])` refuse other events. `AgentNetwork.setup()` throws `NetworkWiringError` for contradictory wiring. `.produce(params)` throws `AgentParamsError`. `expose()` answers malformed JSON and invalid payloads with a 400 before any run starts; with several `triggerEvents` the body must be `{ name, payload }`.
  _Migrate:_ add `.emits([...])` to every agent and tool that emits (`{ reply: true }` for events that only answer an `emitAndAwait`), declare channel events where you rely on them, and send `{ name, payload }` when a route has several trigger events.

- **Tracer hooks get a status.** `NetworkTracer.onRunEnd` and `onAgentInvokeEnd` receive a third argument `{ status: 'ok' | 'error' | 'cancelled' }`; a cancelled run is no longer an error. `RunErrorKind` gained `'run-unavailable'` and `'stream-error'`.
  _Migrate:_ custom tracers should check `options.status` before `error` (for `cancelled`, `error` is still set); exhaustive `switch`es over `error.kind` need the new cases.

- **SSE responses carry ids.** Responses start with an `id:` line and carry `id:` on durable events, plus `: ping` heartbeat comments.
  _Migrate:_ nothing with `EventSource`; hand-written SSE parsers must accept `id:` and `:` comment lines.

- **A dropped stream keeps its run for 30 seconds.** `reconnectWindow` defaults to `'30 seconds'`: a run whose client disconnected keeps going that long so a reconnect (`Last-Event-ID`) continues it live, then it is cancelled.
  _Migrate:_ pass `registerSSEStream({ reconnectWindow: 0 })` to cancel at once, as before.

- **Renamed (no aliases).** `DepedencyLayer` → `DependencyLayer`, and with it `DependencyLayerDef`, `DependencyLayerInstance`, `DependencyLayerValue`, `DependencyLayerInstanceTypeId`, `isDependencyLayerInstance`. A layer definition's `_tag` is `'DependencyLayerDef'` (was `'SkillDependencyDef'`); brand symbols use the `m4trix/` namespace (`Symbol.for('m4trix/DependencyLayerInstance')`, `Symbol.for('m4trix/Done')`).
  _Migrate:_ search and replace `Depedency` → `Dependency`; update code that compares `_tag` or the symbol keys.

- **Removed APIs.**
  - The spawner: `ctx.spawner`, `SpawnerBuilder`, `SpawnFn`, `SpawnCallbackContext`, `network.getSpawnerRegistrations()` and the wiring code `spawner-listen-not-accepted`. _Migrate:_ register agents at setup and vary their behavior per tenant through `principal` and dependency layers.
  - `Proxy.kafka()` and `Proxy.socketIo()`. _Migrate:_ `proxy.custom(kind, config, direction)` or `defineProxyKind(kind)` with `registerCustomProxy`; Kafka and Socket.IO bridges are planned on top of `EventTransport`.
  - The socket.io helpers (`SocketIoFactory`, `SocketEventName`, `BaseMessage`, `TextMessage`, `VoiceMessage`, `Message`, `Role`), the unused LLM, prompt and message-transform helpers, and `Channel.of` / `ChannelDef`.
  - Internal helpers that were exported by accident: `assertLayersProvided`, `assertUniqueLayerNames`, `assertDependencyMatch`, `toLayerArray`, `mergeDependencyLayers`, `toToolArray`, `channelAcceptsEvent`, `channelHasProxy`, `createInboundPublisher`, `createProxyExposeContext`, `createInteractiveStream` (custom proxies still get `ctx.createInteractiveStream`), `resolveChannelsForProxyKind`, `guardNetworkTracer`, `tracerFailureLogger`, `traceEndStatus`, `pickRunLimits`, `resolveRunLimits`, `runEndEnvelope`, `runUnavailableEnvelope`, `streamFailedEnvelope`, `outcomeError`, `outcomeTraceStatus`, `withRunUsage`, `limitExceededOutcome`, `agentFailureOutcome`, `serializeAgentError`, `serializeError`, `storeErrorOutcome`.

- **Packaging.** `effect` is a peer dependency (`^3.20.0`) and no longer installed with the package; Node.js 20+ is required.
  _Migrate:_ `pnpm add effect` next to `@m4trix/core`.

### Features

- **Resumable, hardened SSE**: `Last-Event-ID` (or `?lastEventId=`) resumes a run from the store and continues it live; `ExposeRunNotFoundError` (404) for unknown runs; heartbeats, back-pressure on Express, GET payloads via `?payload=`, safe payload serialization.
- **Run controls**: `endsOn`, `complete()`, `fail()`, `signal` in agents, tools and skills; `idleTimeout`, `maxDuration`; `maxDepth`, `maxEvents`, `maxTokens`, `maxCostUsd` budgets; `reportUsage()` summed per run and model.
- **Concurrency**: per-run mailboxes and ordering, runs in parallel, `.concurrency(n)` per agent, transient events (`{ transient: true }`) that slide instead of blocking, also when only a tool emits them.
- **Stores, tenancy and transport**: pluggable `AgentNetworkStore`, per-principal history, `EventTransport` seam with `createInMemoryTransport()`, `runStoreContract` / `runTransportContract` in `@m4trix/core/testing`.
- **Context folds**: a typed, incremental, budget-aware view of a conversation instead of re-reading `history.context()` on every step.
  - **Folds.** `ContextFold.of(name, { scope?, state?, version? })` folds events from `.initial()` with pure `.on()` handlers, which define the events it reads (one per event: a second one is a type error); the optional `state` schema types the state (`fold.stateSchema`, typed `S.Schema<State, Encoded>`). `SegmentedFold.of(name, { data, summary?, tag? })` keeps atomic segments (a model step with all its tool results) described by schemas: `.open(event, …)` opens a segment, `.attach(event, { kind?, to, onMissing?, update })` updates the one the event belongs to (no such segment: the state stays as it was, and the event is reported unless `onMissing: 'ignore'`), `kind` narrowing a tagged union of segment data through the fold's typed `tag`.
  - **Reading.** Agents and aggregators declare folds (only folds) with `.folds([...])` and read `await ctx.folds.<name>()`: lazily, folded incrementally and cached per context (or run) and fold object on the event plane, bounded by the `foldCache` setup option (`{ maxEntries, ttl }`). The state is typed read-only (`FoldReadStateOf<F>`: the `state` schema's type, or `DeepReadonly<State>` for a fold without one) and frozen at runtime (its plain objects and arrays; `Date`s, `Option`s and class instances are left as they are). Define each fold once, share that object, and give each fold in a network its own name.
  - **Compaction** is core-owned: `await folds.conversation.compact(async (state) => next)` (a context-scoped fold with a `state` schema; `FoldCannotCompact` otherwise) publishes the new state, strictly encoded with the schema (`FoldCompactionError` otherwise), as the fold's checkpoint `m4trix:fold.checkpoint:<name>@<version>`, with `through`, the cursor of the read it was computed from. It is stored with the run on no channel (never delivered or streamed), and every read, warm or cold, restores the newest one and folds the events after `through` on top: nothing published while a summary is written is lost, and concurrent compactions resolve to the newest. `version` selects the checkpoints a fold restores; after a bump the whole history is folded, and summarized, again. A segmented fold also takes the policy `compact({ view, budget, keepTokens, keepFrom?, summarize })`, which compacts only when the view does not fit and something is older than what it keeps, and resolves to `{ compacted, state, summarized }`. Aggregators get read accessors without `compact`. `foldCheckpointEventName()` / `isFoldCheckpointEvent()` name and recognize checkpoints.
  - **Views** are plain functions: `ContextView.of(fold, { strategies?, count?, countSummary? })` (`measure` for folds without segments) returns `view(state, { budget })`, which trims the state to the budget of that call with `ContextStrategy.elide({ keepNewest, … })` (memoized per segment) and `ContextStrategy.dropOldest({ keepFrom })` (`ContextStrategy.fromNewest(fold, kind)` keeps e.g. the current turn, `ContextStrategy.newest(n)` the newest segments), or your own `ContextStrategy`, and reports `{ tokens, overBudget, dropped, fits }`; `fits` (nothing dropped, within budget) is the compaction trigger. A segmented view's `view.count(segment)` and `view.split(state, { keepTokens, keepFrom? })` count and cut the conversation for a compaction that targets a size, without a budget. `approxTokenCount()` is the default counter.
  - **Stored events are decoded** with their event's schema before they are folded (only validated, and passed as stored, for schemas that do not transform), the same way on any store, warm and cold; fields a schema does not know (e.g. removed from it since) are stripped, so a fold that keeps payloads in its state can still be compacted. **Old history never breaks a read**: an event that no longer decodes, a checkpoint that cannot be restored and an event `attach` finds no segment for are left out and reported, once per event plane while it remembers them (the last 1000, least recently seen forgotten first), through the network's `logger` and the `m4trix.fold.read.skipped` metric (`fold`, `reason: 'decode' | 'checkpoint' | 'missing-segment'`).
  - **Checks.** The wiring check warns with `fold-event-unpublished` when nothing publishes a folded event, fails setup with `fold-checkpoint-shared` when different compactable folds of one name and version would share checkpoints, warns with `fold-name-shared` for other folds that share a name, with `event-schema-mismatch` when one event name has different payload schemas across channels, agents and folds, and with `event-not-storable` when a durable event's schema encodes to something JSON cannot hold (e.g. `S.DateFromSelf`). The `m4trix.fold.read.events` metric reports each read (`cold` / `warm` / `reset`).
- **History reads**: `history.context({ names, after })` filters by event name and reads forward from a page's `head` cursor; `history.latest(names)` returns the newest matching event and a cursor (e.g. the latest checkpoint), backed by the optional `AgentNetworkStore.readLatest`. A page read `after` a cursor of a deleted or expired context, or one the store does not recognise (the in-memory store no longer throws on one), comes back from the start of the current history with `reset: true`; `runStoreContract` checks both. A fold checkpoint whose cursor is such a one is ignored. What custom stores must implement for it is under **`AgentNetworkStore` is async and keyed by tenant**.
- **Tools for LLM providers**: JSON Schema from Effect schemas, `toOpenAI()`, `toAnthropic()`, `toAiSdk()`, `executeForModel()`, `.timeout()`, `.retry()`, a trace span per tool call.
- **Observability**: `logger` and `onMetric` setup options (run, agent, mailbox, store and fold metrics, e.g. `m4trix.run.duration_ms`, `m4trix.store.append.errors`, `m4trix.fold.read.skipped`), tracer `onUsage` hook, `network.validate()` wiring check.
- **Explicit public API**: every export is listed by name and recorded in an API report checked in CI; `Envelope` and `DEFAULT_RECONNECT_WINDOW` are exported.
- **Edge runtimes**: no Node built-ins (Vercel Edge, Cloudflare Workers, Deno, Bun), checked in CI; side-effect free (`"sideEffects": false`); CommonJS consumers get their own `.d.cts` types.
- **`NextEndpoint.from(api)` / `ExpressEndpoint.from(api)`** work without options: each request gets fresh run and conversation ids unless `requestToRunId` / `requestToContextId` say otherwise.
