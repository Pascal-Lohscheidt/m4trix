LangGraph — the graph way Python 
# Step 1: import the graph theory
from langgraph.graph import StateGraph, START, END
from langgraph.graph.message import add_messages
from typing_extensions import TypedDict, Annotated
from langchain_openai import ChatOpenAI

# Step 2: define your state shape upfront
class State(TypedDict):
    messages: Annotated[list, add_messages]

# Step 3: define nodes as separate functions
llm = ChatOpenAI(model="gpt-4o")

def call_model(state: State):
    return {"messages": [llm.invoke(state["messages"])]}

# Step 4: construct the graph by hand
graph_builder = StateGraph(State)
graph_builder.add_node("llm", call_model)
graph_builder.add_edge(START, "llm")
graph_builder.add_edge("llm", END)

# Step 5: compile before you can use it
graph = graph_builder.compile()

result = await graph.ainvoke(
    {"messages": [{"role": "user", "content": query}]}
)
m4trix — the event way TypeScript 
// Step 1: name the thing that happens
const UserQuery = AgentNetworkEvent.of(
  'user:query',
  S.Struct({ query: S.String })
)

// Step 2: write the logic — just a function
const llmAgent = AgentFactory
  .run()
  .listensTo([UserQuery])
  .logic(async ({ event }) => ({
    reply: await openai.chat(event.payload.query)
  }))
  .produce({ channel: 'client' })

// Step 3: register — done
const network = AgentNetwork.setup(
  ({ registerAgent }) => {
    registerAgent(llmAgent)
  }
)

✗ TypedDict state, node functions, add_node calls, add_edge wiring, compile step — five distinct concepts before your agent does anything. And that's the simple example. Add conditional routing and you're writing graph topology by hand.
✓ Define what happened (the event), write what to do (the function), say where results go (the channel). TypeScript catches mismatched payloads at compile time. No state machine. No compile step. No Python.

Three steps, then you're wiring agents.

The mental model fits on a napkin. Start with one agent. Grow to a swarm without rewriting anything.

1

Define typed events

Name the thing that happens. Attach a schema. Agents that receive the wrong shape get a compile error, not a runtime crash.

AgentNetworkEvent.of( 'user:query', S.Struct({ query: S.String, userId: S.String }) )
→
2

Write agent logic

A plain async function. Typed input in, typed output out. No graph concepts, no state accumulators, no reducers.

AgentFactory .run() .listensTo([UserQuery]) .logic(async ({ event }) => ({ reply: await llm( event.payload.query ) }))
→
3

Wire to a network

Register one agent or fifty. Expose as SSE, Kafka, or HTTP. Start solo, scale to a swarm — the network doesn't care.

AgentNetwork .setup(({ registerAgent }) => { registerAgent(llmAgent) }) .expose({ channel: 'client' })

Events in. Results out. Agents in between.

Graphs make you define nodes and edges before you've written a single line of business logic.

m4trix agents are async functions that listen to typed events and produce typed outputs. No graph. No global state. Compose into a network when you're ready.

AgentFactory .run() .listensTo([UserQuery]) .logic(async ({ event }) => ({ reply: await llm( event.payload.query ) })) .produce({ channel: 'client' })
type safety

If the schema changes, you'll know before prod.

Effect Schema validates event payloads at runtime and gives you full TypeScript inference through the whole call chain. Wrong shape → compile error.

AgentNetworkEvent.of( 'user:query', S.Struct({ query: S.String }) )
orchestration

One agent today. A swarm when you need it.

Register agents into a network. They share named channels, not a monolithic state object. Add agents incrementally — the network doesn't care how many.

AgentNetwork.setup( ({ registerAgent }) => { registerAgent(orchestrator) registerAgent(llmAgent) registerAgent(toolAgent) } )
routing

Producers don't need to know who's listening.

Named channels decouple agents from each other. Swap a sink without touching agent logic. Route the same channel to HTTP, Kafka, or a custom handler.

createChannel('client') .sink(sink.httpStream())
http adapter

Your network already has an API. Just expose it.

Built-in Next.js and Express adapters wrap your network as a streaming handler. Clients get results as SSE — no boilerplate, no extra infra.

NextEndpoint .from(network.expose({ channel: 'client' })) .handler()
ecosystem
