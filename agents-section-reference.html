Section 2 — Why event-driven?
No graphs. Just events.

The most persuasive content on the page. Show the concrete delta — same outcome, dramatically less ceremony. Engineers read code before prose.

The graph way LangGraph (Python) 
# 1. Define state shape
class AgentState(TypedDict):
    messages: Annotated[list, add_messages]
    next: str

# 2. Define every node separately
def call_model(state):
    ...
def call_tools(state):
    ...
def should_continue(state):
    ...

# 3. Wire the graph by hand
workflow = StateGraph(AgentState)
workflow.add_node("agent", call_model)
workflow.add_node("tools", call_tools)
workflow.set_entry_point("agent")
workflow.add_conditional_edges(
    "agent", should_continue,
    {"continue": "tools", "end": END}
)
workflow.add_edge("tools", "agent")

# 4. Compile before you can use it
graph = workflow.compile()
result = await graph.ainvoke({"messages": [...]})
The m4trix way m4trix/core (TypeScript) 
// 1. Define the event (your schema IS your contract)
const UserRequest = AgentNetworkEvent.of(
  'user:request',
  S.Struct({ query: S.String })
)

// 2. Write logic — just a function
const agent = AgentFactory
  .run()
  .listensTo([UserRequest])
  .logic(async ({ event }) => ({
    response: await llm(event.payload.query)
  }))
  .produce({ channel: 'client' })



// 3. Wire when you're ready — or not yet
AgentNetwork.setup(({ registerAgent }) => {
  registerAgent(agent)
})
✗ State shape, node definitions, conditional edges, compile step — four concepts before your agent does anything.
✓ One event, one function, one network registration. Type errors catch mismatches at compile time — not in prod.
Section 3 — How it works
Three steps, then you're done

Lowers activation energy. Makes the mental model concrete before the feature details.

1

Define typed events

Name the thing that happens. Attach a schema. That's your contract — agents can't receive the wrong shape.

AgentNetworkEvent.of( 'user:request', S.Struct({ query: S.String }) )
2

Write agent logic

A plain async function. Receives the typed event, returns a typed output. No graph concepts, no state machine.

AgentFactory .run() .listensTo([Event]) .logic(async ({ event }) => ({ reply: await llm(event) }) )
3

Wire to a network

Register agents, name your channels, expose as HTTP or Kafka. Start with one agent, scale to a swarm.

AgentNetwork.setup( ({ registerAgent }) => { registerAgent(myAgent) } ).expose({ channel: 'client' })

Section 5 — Feature bento (rewritten)
Everything you need. Nothing you don't.

Cards lead with the problem, then the solution. The code snippet is evidence, not filler. Tag indicates the conceptual layer.

core primitive

Write logic once. Handle any event.

Graphs make you think in nodes and edges before you've written a line of business logic. You're wiring a state machine before you know what state you have.

m4trix agents are just async functions that listen to typed events and produce typed outputs. No graph. No global state. Compose when you're ready.

AgentFactory .run() .listensTo([UserRequest]) .logic(async ({ event }) => ({ reply: await llm(event.payload.query) })) .produce({ channel: 'client' })
type safety

If the schema changes, you'll know before prod.

Effect Schema validates event payloads at runtime and gives you full TypeScript inference. Wrong shape → compile error, not a 3am alert.

AgentNetworkEvent.of( 'user:request', S.Struct({ query: S.String }) )
orchestration

One agent today. A swarm when you need it.

Register agents into a network. They share named channels, not a monolithic state object. Add agents incrementally — the network doesn't care how many.

AgentNetwork.setup( ({ registerAgent }) => { registerAgent(orchestrator) registerAgent(llmAgent) } )
routing

Producers don't need to know who's listening.

Named channels decouple agents from each other. Route to HTTP streams, Kafka, or write your own sink. Swap the sink without touching agent logic.

createChannel('client') .sink(sink.httpStream())
http adapter

Your network already has an API. Just expose it.

Built-in Next.js and Express adapters wrap your network as a streaming HTTP handler. No boilerplate. Clients receive events as SSE.

NextEndpoint .from(network.expose({ channel: 'client' })) .handler()
ecosystem

Same mental model, all the way down.

Core handles orchestration. Stream handles async pipes. React gives you hooks. UI gives you components. All from the same team, the same versioning — no glue code between layers.

@m4trix/core // agents & networks @m4trix/stream // async pipes @m4trix/react // hooks — useAgentStream() @m4trix/ui // pre-built components
